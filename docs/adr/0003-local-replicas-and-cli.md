# ADR 0003: Shared local replicas and an Android/JVM editing CLI

Status: accepted, 2026-10-11. Extends ADR 0001; supersedes exclusive Activity
ownership of the local event/outbox file and stroke-only rendering.

Updated by [ADR 0004](0004-local-proxy-and-incremental-state.md): local command
proxy, journal transactions, cached incremental models and asynchronous ink
replace full-file saving and per-edit replay described below.

## Context

Agents most commonly need to draw a labeled diagram on a new layer. App and CLI
must collaborate on one Android device without a server. Desktop CLI replicas
must also synchronize with a tablet through either a desktop or Phenom II server.
Multiple actors may share one device; multiple devices keep independent replicas.
Predictable automatic conflict resolution is preferred to conflict dialogs.
Agent orchestration is outside this project.

## Decision

Add `apps/cli` and `packages/core`. Use dependency-free Java 8-compatible source,
compiled with the root Nix shell's JDK 17 to JVM bytecode and with Android d8 to
DEX. The existing APK includes the CLI and core. JVM runtime plus Java2D supplies
Linux PNG rendering; Android Canvas supplies Android PNG. Both consume the same
scene traversal; SVG is generated by the shared renderer. No native CPU extensions
or large runtimes/models are required on Phenom II beyond a JVM if a CLI is run
there. The server remains Python/SQLite; no remote deployment is required.

The app launches an `app_process` child with its installed APK as CLASSPATH and
its own UID/private state path. This follows Android's [app_process entry point](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android15-platform-release/cmds/app_process/app_main.cpp).
It avoids extracting native executables into writable app storage. Actual app-UID
launch is covered on the API 36 emulator; BOOX firmware remains a hardware check.
PNG export in the child initializes a small font map when `Typeface.DEFAULT` is
absent. It reads Roboto (or `NOTEMAKER_FONT`) and calls framework methods
`initSystemDefaultTypefaces` and `setSystemFontMap`; app UIDs cannot read Android's
full system fallback configuration directly. These methods are not public SDK
APIs; they are isolated in the Android PNG adapter and covered by the app-spawn
test. See Android's [Typeface initialization](https://android.googlesource.com/platform/frameworks/base.git/+/master/graphics/java/android/graphics/Typeface.java).
Firmware changes may require updating that adapter. Exported text uses that
font's character coverage; ordinary app text retains Android's full fallback map.
SVG and local actions do not depend on this initialization.

The data graph is app—local replica, CLI—local replica, replica—optional server.
There are no app/CLI editing paths that bypass the replica. Preserve existing
`document-<UUID>.json` files, event/outbox/cursor fields, and UI preferences.
Introduce actor histories, local revision, document name and pinned server identity
lazily without destroying existing data. New fields are preserved by every writer.

All processes use a stable sibling lock file and atomic fsynced file replacement.
The shared core also serializes threads per canonical path because JVM
[FileChannel locks](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/nio/channels/FileChannel.html)
are process-wide, not thread locks. The parent directory is fsynced after rename.
A separate sync lock serializes workers without blocking edits on HTTP requests.
A catch-up merges into the latest locked state, never a stale in-memory copy.
Only acknowledged IDs from the sent snapshot leave the outbox, after all pages
have been read. An independent app watcher notices local edits every 200 ms even
when the network worker is waiting or failing. Idle state does not redraw.

The app syncs while running and resumes on reopening. A desktop CLI performs local
actions and uses explicit `sync` or a reconnecting `watch` process. No always-on
Android service or agent runner is introduced. The server exposes a persisted
UUID; replicas reject a different database after binding to avoid silent cursor
loss. A legacy replica's first upgraded sync must still reach its original server.

Extend the operation log with atomic `batch` actions, editable `object` snapshots,
and separate object/layer active registers. A new diagram is a layer, nodes,
labels, connectors and activation records in one batch/sequence entry. Snapshot
and active registers resolve independently in server commit order. Locally pending
operations remain optimistic until acknowledged and caught up. This is an ordered
operation-log model, not a CRDT or an integration with Google Docs internals.

Objects support rectangles, ellipses, text and arrows. Arrows may attach to node
boundaries by stable ID. App Canvas, CLI PNG/SVG, layer thumbnails, and browser
viewer all render them. The app offers a geometry/label editor and erasure/restore;
the CLI offers structured inspection and patching. The entire diagram is one
undoable action for its actor. Explicit actor/session IDs persist across CLI calls.
Existing app stroke undo remains compatible with its existing history.

Every future drawing/document action must be exposed through the CLI with
structured input/output, implemented through the shared action/state boundary,
and tested by calling the actual CLI. This rule is also in root `AGENTS.md`.

## Consequences and limitations

Older client versions do not understand batch/object events: upgrade app, CLI and
server together before introducing diagrams. Existing v1 stroke logs remain valid.
Server ordering preserves deterministic eventual convergence; simultaneous field
changes to one snapshot can overwrite each other. Erasure is independent, so a
move cannot resurrect an erased object. Undo restores snapshots and can overwrite
later edits to the same entity; it is actor-scoped compensating undo, not selective
collaborative undo. Restoring history is itself a new shared action.

The JSON replica is appropriate for the existing small prototype and preserves
migration simplicity. Every mutation rewrites it, replay is linear in event count,
and there is no compaction. Use local filesystems with reliable locks/atomic rename.
Large notebooks will require a transactional database or segmented journal before
scaling; the Store boundary makes that a storage implementation change.

Labels are plain text with explicit line breaks, no rich text or automatic layout.
The agent supplies diagram geometry. Raster text appearance depends on platform
fonts. There is no drag-based object selection UI yet; objects are edited through
Notes → Edit diagram objects or the CLI. No AI provider or orchestration is added.

## Verification

`tests/cli_checks.py` calls real JVM CLI processes and the real server to cover
concurrent local writers, history, atomic validation, offline edits, merge rules,
pagination, migration, retries, and PNG/SVG export. `tests/cli_android.py` launches
the CLI as an app child on an isolated emulator, draws concurrently while offline,
checks shared state/history/export, reconnects desktop and tablet through a real
server, and checks browser replay. Existing app integration remains a regression
check. Executed results are recorded in `docs/verification.md`.
